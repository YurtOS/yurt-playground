Upcoming

Updated 2026-10-28 · not released yet; plans may change

Work that is in progress or in review for a later train. None of it is on the live playground yet.

Dynamic loading (dlopen)

  • The kernel and libc sides of dlopen ship in playground-2026.10.20-22366ef. Still in progress: a shared libc.so, so ordinary CPython native extensions can load (yurt-toolchain #180, #236; yurt-ports #173).
  • Thread-local storage in runtime-loaded libraries ships for the desktop host in playground-2026.10.26-3d32068; the browser-host half is in progress (kernel #4034).

JavaScript JIT (experimental)

Node on Yurt runs SpiderMonkey's interpreter. The JIT work adds a tier that compiles hot JavaScript to WebAssembly inside the guest (NightMonkey) and mounts it through the kernel's JIT interface. It is not in the image and stays off by default.

  • Opt-in node build with NightMonkey (yurt-node #42), for measurements. On the desktop host, Octane benchmarks ran 2–47× faster and hot loops up to 178×. Compiling costs 0.3–24 s per run, only the first batch of code is compiled so far, and Gemini CLI does not speed up yet.
  • Kernel: JIT code now survives fork on the desktop host (kernel #3677). Still open: slot reservation and module loads over 1 MiB on the browser host (#2981, #3319), and fork and checkpoints across JIT frames (#3335). Tracked in yurt-ports #110.

Go

  • Go runs on Yurt as Linux: yurt-go adds a GOOS=linux GOARCH=wasm32 port on top of upstream Go's wasm32 work (golang/go#63131, not merged upstream yet). Go programs build into ordinary Yurt processes that use Linux system calls, not WASI.
  • The Go toolchain runs inside the sandbox: the yurt-ports go package (Go 1.28.0-devel, 59.4 MB) installs go and gofmt under /usr/lib/go, so go build and go test work in a sandbox. The GitHub CLI (gh) is built with it.
  • Neither is in the playground image; both install as packages. Go programs run on one thread, and signals reach them only between system calls.

Later trains

  • Root can search and create in a directory that has no execute bits, as on Linux (#3714).

Planned

  • Ctrl-C and kill -INT reach a CPU-bound Python program, so KeyboardInterrupt works (#2811).
