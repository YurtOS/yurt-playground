Packages

Updated 2026-10-31 · released independently of trains

Packages come from the signed YurtOS/yurt-packages repository and are published on their own schedule, not with a train. In a sandbox with a network, sudo pkg update then sudo pkg install NAME installs the newest version, and sudo pkg upgrade moves to newer ones. In the browser the Packages panel does the same. pkg verifies every signature before it installs anything.

New on 2026-10-31: in the browser, sudo pkg update and sudo pkg install NAME now work in the terminal too. The page fetches the signed files from the package repository for pkg, and only from there; programs in the sandbox still have no network of their own. The terminal and the Packages panel share one cache, so a package installed in one shows up in the other.

  • Node.js is in the image. /usr/bin/node is Node v22.23.3 on Yurt (build yurt.2), with Node's own lib/ running on SpiderMonkey over libuv.
  • Gemini CLI 0.64.0 is in the image as /usr/bin/gemini. It's a single bundle with no dependency tree. 0.64.0 fixes the project-registry race that broke 0.35.1. Auto-update is turned off in /etc/gemini-cli/settings.json. You need your own Gemini API key to use it.
  • getconf is in the image. BusyBox has no getconf, and Node programs call getconf LONG_BIT.

yurt CLI and desktop host

  • yurt exec -i forwards signals and exits when its client goes away, and -t passes TERM through.
  • The yurt daemon now runs its idle reaper. The new --sandbox-idle-timeout flag controls it.
  • sandboxes.json is written under a lock, starting from the latest copy, so concurrent commands no longer lose each other's changes.

Not in this release

  • Checkpoint sealing is reverted in this train. It needs programs built for checkpoints, which ship with Guest SDK 0.0.27 and later, and it will come back with that SDK.
  • Guest SDK 0.0.27 is published, but the playground still uses 0.0.26. 0.0.27 is the first SDK without Rust, and moving to it is still in progress.
  • Recent Node.js fixes aren't in the image yet. They need a new Node.js build.

Known issues

  • Gemini CLI takes a long time to start the first time in the browser (JS host). Startup under the desktop host is quicker.
