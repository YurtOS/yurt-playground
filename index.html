This train brings Node.js and Gemini CLI 0.64.0 to the playground image, along with a set of kernel and CLI fixes.

Guest SDK 0.0.26 (unchanged)

Highlights

  • Node.js is in the image. /usr/bin/node is Node v22.23.3 on Yurt (yurt-node release node-v22.23.3-yurt.2), with Node's own lib/ running on SpiderMonkey over libuv.
  • Gemini CLI 0.64.0 is in the image as /usr/bin/gemini. It's a single bundle with no dependency tree. 0.64.0 fixes the project-registry race that broke 0.35.1 (yurt-ports #217). Auto-update is turned off in /etc/gemini-cli/settings.json. You need your own Gemini API key to use it.
  • getconf is in the image. BusyBox has no getconf, and Node programs call getconf LONG_BIT.

yurt CLI and desktop host

  • yurt exec -i forwards signals and exits when its client goes away, and -t passes TERM through (#327).
  • sandboxd actually runs the idle reaper. The new --sandbox-idle-timeout flag controls it (#326).
  • sandboxes.json is written under a lock, starting from the latest copy, so concurrent commands no longer lose each other's changes (#325).

Not in this release

  • The host_checkpoint seal work (kernel #3497, #3498, #3499) is reverted in this train. It needs checkpoint-typed guests, which ship with Guest SDK 0.0.27 and later, and it will come back with that SDK.
  • Guest SDK 0.0.27 is published, but the playground still uses 0.0.26. 0.0.27 is the first SDK without Rust, and moving to it is still in progress.
  • Recent yurt-node fixes (yurt-node #29, #31, #33, #36) aren't in the image yet. They need a new yurt-node release.

Known issues

  • Gemini CLI takes a long time to start the first time in the browser (JS host). Startup under the desktop host is quicker.
